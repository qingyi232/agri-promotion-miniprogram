================================================================================
一、项目概述
================================================================================

项目名称：农产品推广协同链小程序
项目类型：微信小程序（云开发）
项目功能：展示农产品故事，支持浏览、搜索、分类筛选、点赞、收藏、
          评论、浏览记录等社交互动功能。

核心功能清单：
  1. 首页故事列表 + 详情页（轮播图、分类筛选、搜索、分页加载）
  2. 点赞功能（点赞/取消点赞，实时更新计数）
  3. 推荐页（热门故事、分类推荐、瀑布流布局）
  4. 评论功能（发表评论、评论列表展示）
  5. 收藏/浏览记录（收藏/取消收藏、自动记录浏览历史、清空记录）
  6. AI 智能创作（输入农产品关键词，AI 生成推广故事，提交审核）
  7. 青年策展人中心（投稿管理，待审核/进行中/已完成状态流转）


================================================================================
二、技术栈
================================================================================

前端：
  - 微信小程序原生框架（WXML + WXSS + JavaScript）
  - 不依赖任何第三方 UI 框架，纯原生开发

后端：
  - 微信云开发（CloudBase）
  - 云函数：Node.js 运行环境
  - 云数据库：文档型数据库（类似 MongoDB）
  - 服务端 SDK：wx-server-sdk v2.6.3

================================================================================
四、前端页面说明
================================================================================

本项目共 8 个页面，3 个 TabBar 页面 + 5 个子页面。

----------------------------------------------------------------------
4.1 首页（pages/index/index）—— TabBar 页面
----------------------------------------------------------------------
文件：index.js / index.wxml / index.wxss / index.json

功能：
  - 顶部搜索栏：输入关键词搜索故事（按标题模糊匹配）
  - 轮播图横幅：展示标记为 isBanner=true 的故事，点击跳转详情
  - 分类标签栏：全部/水果/蔬菜/粮油/茶叶/药材/畜牧，点击筛选
  - 故事卡片列表：展示封面图、标签、标题、摘要、作者、点赞数、评论数
  - 下拉刷新 + 上拉加载更多（分页，每页10条）
  - 点赞图标根据当前用户是否点赞显示红色实心/灰色空心

数据来源：
  - 轮播图：调用 stories 云函数 action='getBanners'
  - 故事列表：调用 stories 云函数 action='getList'

关键逻辑：
  - onLoad 时先等待云环境就绪（app.waitCloudReady），再串行加载数据
  - callCloud 封装函数带 1 次自动重试机制

----------------------------------------------------------------------
4.2 详情页（pages/detail/detail）—— 子页面
----------------------------------------------------------------------
文件：detail.js / detail.wxml / detail.wxss / detail.json

功能：
  - 封面大图展示
  - 标签、标题、作者信息、发布时间
  - 富文本内容展示（使用 rich-text 组件）
  - 故事图片集（点击可全屏预览）
  - 产地信息卡片（产地、应季时间、特色）
  - 互动数据展示（点赞数、评论数、浏览数）
  - 评论列表（头像、昵称、时间、内容）
  - 底部操作栏：写评论入口、点赞按钮、收藏按钮
  - 评论输入弹窗（textarea + 字数统计 + 发送按钮）
  - 分享功能（onShareAppMessage）

数据来源：
  - 故事详情：stories 云函数 action='getDetail'（同时 viewCount+1）
  - 评论列表：comments 云函数 action='getList'
  - 点赞状态：likes 云函数 action='check'
  - 收藏状态：favorites 云函数 action='check'

用户操作 → 数据库变化：
  - 点赞：likes 集合新增记录 + stories.likeCount+1
  - 取消点赞：likes 集合删除记录 + stories.likeCount-1
  - 收藏：favorites 集合新增记录
  - 取消收藏：favorites 集合删除记录
  - 发评论：comments 集合新增记录 + stories.commentCount+1
  - 浏览：history 集合新增/更新记录 + stories.viewCount+1

----------------------------------------------------------------------
4.3 推荐页（pages/recommend/recommend）—— TabBar 页面
----------------------------------------------------------------------
文件：recommend.js / recommend.wxml / recommend.wxss / recommend.json

功能：
  - 顶部标题区（为你推荐 + 副标题）
  - 分类标签栏（带图标，横向滚动）
  - 热门故事横向滚动卡片（按点赞数排序，取前6条）
  - 瀑布流双列布局（按点赞数+时间排序，取前20条）
  - 点赞图标根据用户状态切换红色/灰色

数据来源：
  - 热门故事：stories 云函数 action='getHot'
  - 推荐列表：stories 云函数 action='getRecommend'

----------------------------------------------------------------------
4.4 个人中心页（pages/profile/profile）—— TabBar 页面
----------------------------------------------------------------------
文件：profile.js / profile.wxml / profile.wxss / profile.json

功能：
  - 用户头像和昵称展示（未登录显示默认头像+登录按钮）
  - 数据统计行：收藏数、浏览数、点赞数、评论数（实时从数据库查询）
  - 青年策展人中心卡片：显示待审核/进行中/已完成统计，点击进入详情
  - 功能菜单：AI创作故事、策展人中心、我的收藏、浏览记录、我的点赞、
              分享给朋友、关于我们
  - 最近浏览横向滚动卡片（最近10条浏览记录）
  - 统计数字可点击跳转到对应列表页

数据来源：
  - 统计数据：history 云函数 action='getStats'（聚合查询4个集合的count）
  - 策展统计：curator 云函数 action='getStats'
  - 最近浏览：history 云函数 action='getRecent'

----------------------------------------------------------------------
4.5 收藏/点赞列表页（pages/favorites/favorites）—— 子页面
----------------------------------------------------------------------
文件：favorites.js / favorites.wxml / favorites.wxss / favorites.json

功能：
  - 顶部标签切换：我的收藏 / 我的点赞
  - 列表展示：封面图、标题、摘要、作者、时间
  - 点击跳转详情页
  - 空状态提示
  - onShow 时自动刷新（从详情页返回后同步最新状态）

数据来源：
  - 收藏列表：favorites 云函数 action='getList'
  - 点赞列表：likes 云函数 action='getList'

----------------------------------------------------------------------
4.6 浏览记录页（pages/history/history）—— 子页面
----------------------------------------------------------------------
文件：history.js / history.wxml / history.wxss / history.json

功能：
  - 按日期分组展示（今天、昨天、具体日期）
  - 每条记录显示封面图、标题、摘要、作者、浏览时间
  - 清空记录按钮（二次确认弹窗）
  - 点击跳转详情页
  - onShow 时自动刷新

数据来源：
  - 浏览记录：history 云函数 action='getList'
  - 清空记录：history 云函数 action='clear'

----------------------------------------------------------------------
4.7 策展人中心页（pages/curator/curator）—— 子页面
----------------------------------------------------------------------
文件：curator.js / curator.wxml / curator.wxss / curator.json

功能：
  - 顶部绿色渐变统计卡片：待审核/进行中/已完成数量
  - 标签筛选栏：全部/待审核/进行中/已完成
  - 投稿列表：状态标签（橙色待审核/蓝色进行中/绿色已完成）、
              AI标记（紫色标签）、标题、摘要、分类、审核备注、时间
  - 点击统计数字可快速筛选对应状态
  - 首次进入自动初始化20条示例数据（3待审核+5进行中+12已完成）
  - onShow 时自动刷新（提交新故事后返回可看到最新数据）

数据来源：
  - 策展统计：curator 云函数 action='getStats'
  - 策展列表：curator 云函数 action='getList'

----------------------------------------------------------------------
4.8 AI 创作故事页（pages/ai-story/ai-story）—— 子页面
----------------------------------------------------------------------
文件：ai-story.js / ai-story.wxml / ai-story.wxss / ai-story.json

功能：
  - 顶部深绿渐变介绍区（AI图标+标题+说明）
  - 输入表单：农产品名称（必填）、产品分类（6选1）、补充描述（选填）
  - AI 生成按钮：点击后模拟1.5-2.5秒生成延迟
  - 生成结果展示：标题、正文摘要、标签（左侧绿色竖线装饰）
  - 操作按钮：「提交审核」将故事提交到策展人中心、「重新生成」换一个版本
  - 内置6个分类共12套故事模板，根据用户输入动态填充生成

数据来源：
  - 故事生成：前端本地模板引擎（storyTemplates 对象）
  - 提交审核：curator 云函数 action='submit'

入口位置：
  - 首页右下角「AI创作」悬浮按钮
  - 个人中心菜单「AI 创作故事」


================================================================================
五、云函数说明
================================================================================

所有云函数位于 cloudfunctions/ 目录下，每个云函数是一个独立的
Node.js 项目，包含 index.js（逻辑代码）和 package.json（依赖配置）。

所有云函数统一使用 wx-server-sdk v2.6.3，通过 event.action 参数
区分不同的操作类型。共 7 个云函数。

----------------------------------------------------------------------
5.1 stories 云函数（故事相关）
----------------------------------------------------------------------
文件：cloudfunctions/stories/index.js

支持的 action：
  getList      获取故事列表（支持分类筛选、关键词搜索、分页）
  getDetail    获取故事详情（同时浏览量+1）
  getBanners   获取轮播图数据（isBanner=true 的故事）
  getHot       获取热门故事（按点赞数排序）
  getRecommend 获取推荐故事（按点赞数+时间排序，支持分类）

特殊逻辑：
  getList、getHot、getRecommend 返回数据时，会批量查询当前用户
  在 likes 集合中的点赞记录，给每条故事附带 isLiked 字段，
  用于前端显示红色/灰色心形图标。

----------------------------------------------------------------------
5.2 comments 云函数（评论相关）
----------------------------------------------------------------------
文件：cloudfunctions/comments/index.js

支持的 action：
  getList    获取某篇故事的评论列表（按时间倒序，最多100条）
  add        发表评论（同时 stories.commentCount+1）

特殊逻辑：
  发表评论时会尝试从 users 集合获取用户昵称和头像，
  如果没有则使用默认值「农产品爱好者」。

----------------------------------------------------------------------
5.3 likes 云函数（点赞相关）
----------------------------------------------------------------------
文件：cloudfunctions/likes/index.js

支持的 action：
  check    检查当前用户是否点赞了某篇故事
  like     点赞（likes 集合新增 + stories.likeCount+1）
  unlike   取消点赞（likes 集合删除 + stories.likeCount-1）
  getList  获取当前用户的点赞列表

特殊逻辑：
  点赞时会同时保存故事的标题、封面图、摘要等信息到 likes 集合，
  这样在「我的点赞」列表页可以直接展示，无需再次查询 stories 集合。

----------------------------------------------------------------------
5.4 favorites 云函数（收藏相关）
----------------------------------------------------------------------
文件：cloudfunctions/favorites/index.js

支持的 action：
  check    检查当前用户是否收藏了某篇故事
  add      收藏（favorites 集合新增）
  remove   取消收藏（favorites 集合删除）
  getList  获取当前用户的收藏列表

特殊逻辑：
  与 likes 类似，收藏时也会冗余保存故事信息。

----------------------------------------------------------------------
5.5 history 云函数（浏览记录相关）
----------------------------------------------------------------------
文件：cloudfunctions/history/index.js

支持的 action：
  record     记录浏览（已存在则更新时间，不存在则新增）
  getList    获取当前用户的全部浏览记录（按时间倒序，最多100条）
  getRecent  获取最近浏览记录（默认10条，用于个人中心展示）
  getStats   获取统计数据（聚合查询 favorites/history/likes/comments 的 count）
  clear      清空当前用户的所有浏览记录

----------------------------------------------------------------------
5.6 init 云函数（数据初始化）
----------------------------------------------------------------------
文件：cloudfunctions/init/index.js

支持的 action：
  initData   初始化示例数据（10篇故事 + 6条评论）
  resetData  重置数据（清空后重新初始化）
  fixImages  修复失效的图片链接

特殊逻辑：
  - initData 会先调用 ensureCollections() 自动创建所需的 5 个数据库集合
  - 如果 stories 集合已有数据，会跳过初始化（防止重复）
  - 前端通过 localStorage 标记 data_initialized_v4 避免重复调用
  - fixImages 通过 localStorage 标记 images_fixed_v1 避免重复调用

----------------------------------------------------------------------
5.7 curator 云函数（策展人中心）
----------------------------------------------------------------------
文件：cloudfunctions/curator/index.js

支持的 action：
  getStats      获取当前用户的策展统计（待审核/进行中/已完成数量）
  getList       获取当前用户的投稿列表（支持按状态筛选）
  submit        提交新故事（来源标记为 ai 或 manual）
  updateStatus  更新投稿状态（模拟审核流程）
  initSample    初始化示例数据（20条，含3种状态）

特殊逻辑：
  - getStats 首次调用时如果没有数据，会自动调用 initSample 初始化
    20条示例数据（3待审核+5进行中+12已完成），确保页面不为空
  - 自动创建 curator_stories 集合（如不存在）
  - 每条投稿记录包含 source 字段标记来源（ai/manual）


================================================================================
六、数据库集合说明
================================================================================

本项目使用 6 个数据库集合，全部由云函数自动创建。

----------------------------------------------------------------------
6.1 stories 集合（故事/文章）
----------------------------------------------------------------------
字段说明：
  _id           string    文档ID（自动生成）
  title         string    故事标题
  summary       string    故事摘要
  content       string    故事正文（HTML格式，用于 rich-text 渲染）
  coverImage    string    封面图URL
  images        array     故事图片集URL数组
  category      string    分类（fruit/vegetable/grain/tea/herb/livestock）
  tags          array     标签数组（如 ["水果","脐橙","赣州"]）
  authorName    string    作者名称
  authorAvatar  string    作者头像URL
  origin        string    产地
  season        string    应季时间
  feature       string    特色描述
  likeCount     number    点赞总数（实时更新）
  commentCount  number    评论总数（实时更新）
  viewCount     number    浏览总数（实时更新）
  isBanner      boolean   是否在轮播图展示
  createTime    number    创建时间戳

----------------------------------------------------------------------
6.2 comments 集合（评论）
----------------------------------------------------------------------
字段说明：
  _id           string    文档ID
  storyId       string    关联的故事ID

----------------------------------------------------------------------
8.1 callCloud 封装函数（所有页面通用）
----------------------------------------------------------------------
  每个页面 JS 文件顶部都有一个 callCloud 函数：

  function callCloud(name, data, retries = 1) {
    return new Promise((resolve, reject) => {
      const attempt = (n) => {
        wx.cloud.callFunction({ name, data })
          .then(resolve)
          .catch(err => {
            if (n > 0) {
              setTimeout(() => attempt(n - 1), 500)
            } else {
              reject(err)
            }
          })
      }
      attempt(retries)
    })
  }

  作用：封装 wx.cloud.callFunction，增加自动重试机制。
  当云函数调用失败时，会等待 500ms 后自动重试 1 次，
  提高在网络不稳定时的成功率。

----------------------------------------------------------------------
8.2 批量查询点赞状态（stories 云函数）
----------------------------------------------------------------------
  async function batchCheckLiked(storyIds, openid) {
    const res = await db.collection('likes')
      .where({
        openid,
        storyId: _.in(storyIds)
      })
      .field({ storyId: true })
      .get()
    const likedMap = {}
    res.data.forEach(item => {
      likedMap[item.storyId] = true
    })
    return likedMap
  }

  作用：一次性查询当前用户对多篇故事的点赞状态。
  使用 _.in() 操作符批量匹配，避免逐条查询，提高性能。
  返回一个 { storyId: true } 的映射对象。

----------------------------------------------------------------------
8.3 onShow 防重复调用机制
----------------------------------------------------------------------
  多个页面使用 _loaded 标记避免 onLoad 和 onShow 重复调用：

  onLoad() {
    this.loadData()
  },
  onShow() {
    if (this.data._loaded) {
      this.loadData()    // 非首次：刷新数据
    } else {
      this.setData({ _loaded: true })  // 首次：跳过（onLoad已调用）
    }
  }

  原因：小程序页面首次加载时 onLoad 和 onShow 会依次触发，
  如果两个都调用加载函数，会导致重复请求。
  _loaded 标记确保首次只在 onLoad 中加载，后续切换回来时在 onShow 中刷新。

----------------------------------------------------------------------
8.4 数据冗余存储策略
----------------------------------------------------------------------
  likes、favorites、history 集合中都冗余存储了故事的
  title、coverImage、summary、authorName 等字段。

  优点：
  - 「我的收藏」「我的点赞」「浏览记录」列表页可以直接展示，
    无需再关联查询 stories 集合，减少云函数调用次数
  - 提高列表加载速度

  缺点：
  - 如果故事信息修改，冗余数据不会自动同步
  - 对于本项目（故事内容基本不变）影响可忽略
